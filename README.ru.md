# Fanvil для Home Assistant

[English](README.md) | **Русский**

Локальная интеграция Home Assistant для **IP-домофонов Fanvil**. Видео с камеры, открытие двери,
кто звонит, события панели в автоматизациях — напрямую через HTTP API устройства, без облака.

## Возможности

| | |
|---|---|
| 📹 **Камера** | Живое видео (RTSP, H.264): основной и дополнительный поток, снимки, звук по желанию |
| 🔔 **Дверной звонок** | Кнопка вызова как событие звонка в Home Assistant |
| 🚪 **Журнал открытий** | Кто и как открыл дверь (карта, PIN-код, звонок, кнопка выхода, API) и неудачные попытки |
| 🔊 **Динамик** | Синтез речи и аудиофайлы через динамик панели, ползунок громкости |
| 🔓 **Реле двери** | Кнопка «Открыть» (импульс) и переключатель «Держать открытым» для каждого реле; состояние меняется мгновенно |
| 📞 **Звонки** | Входящий, исходящий, ответ, завершён, пропущенный — события с номером звонящего |
| ☎️ **SIP** | Регистрация, номер и сервер каждой SIP-линии |
| 🚪 **Входы и события панели** | Датчик двери / кнопка выхода, кнопка вызова, вскрытие корпуса, движение, загрузка |
| ⚙️ **Обслуживание** | Перезагрузка, прошивка, IP-адрес, время работы, диагностика |

- **События сразу.** Интеграция сама настраивает на панели *Action URL* — панель сообщает о событиях
  в вебхук Home Assistant. Опрос API остаётся страховкой.
- **Уживается с другими системами.** Action URL, уже занятые другой системой (CRM, АТС, СКУД),
  интеграция не перезаписывает; Action URL можно выключить совсем.
- **Следит за DHCP.** Если панель получила новый IP-адрес, интеграция подхватит его сама.
- **Только локально.** Без облака и без доработок на панели.

## Поддерживаемые устройства

| Серия | Модели | Статус |
|---|---|---|
| Домофоны (вызывные панели) | **i60, i60K, i62** | ✅ Поддерживаются (проверено: i60K и i62, прошивка 2.12.51) |
| Домофоны (вызывные панели) | i61, i63, i64, i66, i67, i68, i62-2 Wire, i64-2 Wire | 🧪 Базовые функции должны работать, ещё не проверено |
| Внутренние мониторы | i501, i504, i506, i51W, i52W, i53W, H501 и другие | 🔜 В планах |
| Интеркомы | серии i10S, i16S, A10 | 🔜 В планах |

У домофонов, мониторов и интеркомов Fanvil общий HTTP API, поэтому новые модели — в основном вопрос
проверки. Есть устройство не из списка — создайте issue, отчёты с реального железа очень помогают.

Нужен **Home Assistant 2026.10** или новее.

## Установка

### HACS (рекомендуется)

1. HACS → ⋮ → **Пользовательские репозитории** → `https://github.com/NikitaKorneev/fanvil-homeassistant`,
   тип **Интеграция**.
2. Найдите **Fanvil** в HACS и скачайте.
3. Перезапустите Home Assistant.

### Вручную

Скопируйте `custom_components/fanvil` в `/config/custom_components/fanvil` и перезапустите Home Assistant.

## Настройка

**Настройки → Устройства и службы → Добавить интеграцию → Fanvil**

| Поле | Значение |
|---|---|
| Адрес | IP или имя панели, без `http://` |
| Порт | 80 (или порт HTTPS) |
| Логин / пароль | учётные данные HTTP API (по умолчанию `admin` / `admin`) |
| Авторизация | Basic (есть и Digest) |

Видео RTSP использует те же логин и пароль.

**Параметры** (кнопка **Настроить** у интеграции):

| Параметр | По умолчанию | Назначение |
|---|---|---|
| Настраивать Action URL на панели | вкл | Прописать на панели адреса вебхука для мгновенных событий |
| Адрес Home Assistant для панели | автоматически | Указать вручную, если панель не достаёт до найденного адреса |
| Интервал опроса | 30 с | Как часто читать состояние через HTTP API |

## Сущности

| Сущность | Описание |
|---|---|
| `camera` Видео: основной поток | `camera.<устройство>_main_stream`: основной поток RTSP (например, 1280×720), снимок через API |
| `camera` Видео: дополнительный поток | `camera.<устройство>_sub_stream`: поток пониже (например, 640×480, ~0,5 Мбит/с) для дашбордов и телефона |
| `binary_sensor` Реле N активно, Вход N разомкнут | Фактические состояния реле и входов |
| `event` Звонок в дверь | `ring` при нажатии кнопки вызова (класс *doorbell*) |
| `event` Дверь | `opened` / `denied` из журнала открытий (атрибуты: `method`, `user`, `relay`, `card`, `sip_number`, `reason`) |
| `event` Звонок | `incoming`, `outgoing`, `answered`, `ended`, `missed` (атрибуты: `remote`, `display_remote`, `line`, `duration`) |
| `event` Событие панели | `key`, `input_N_triggered` / `input_N_reset`, `boot`, `tamper`, `motion` |
| `media_player` Динамик | Синтез речи и звук на панели (`tts.speak`, `media_player.play_media`) |
| `number` Громкость | 0–9, ставит сразу громкость разговора, звонка и сигналов (разговор не ниже 1); три значения панели в атрибутах |
| `button` Открыть реле N (импульс) | Открывает реле на время, заданное на панели |
| `switch` Реле N (держать открытым) | Включён, пока реле удерживается этим выключателем; импульс, карта или звонок его не включают |
| `switch` Звук в камере | Настройки: звук с микрофона в обоих потоках камеры |
| `button` Перезагрузка | Перезагружает панель (настройки) |
| `sensor` Последнее открытие двери | Диагностика: время последней записи журнала; способ, жилец и результат в атрибутах |
| `sensor` Состояние вызова, линия N | Диагностика: состояние линий как есть (основная сущность — событие *Звонок*) |
| `sensor` Номер SIP N, Код регистрации SIP N; `binary_sensor` SIP N зарегистрирован | Диагностика: SIP |
| `sensor` Action URL | Диагностика: `on` / `partial` (часть событий у другой системы) / `off` |
| `sensor` Прошивка, IP-адрес, Время работы | Диагностика |

Имена камер начинаются одинаково, поэтому на странице устройства оба потока стоят рядом в начале
списка. При обновлении с 0.4.0 `camera.<устройство>` переименовывается в
`camera.<устройство>_main_stream` (если вы не меняли entity ID сами) — поправьте дашборды и
автоматизации со старым ID.

Каждое событие дублируется в шину как `fanvil_event` (`device_id`, `event`, данные звонка).

### Примеры автоматизаций

Сказать что-то у двери:

```yaml
action: tts.speak
target:
  entity_id: tts.home_assistant_cloud
data:
  media_player_entity_id: media_player.fanvil_i60k_speaker
  message: "Оставьте, пожалуйста, посылку у двери"
```

Уведомление о звонке в дверь:

```yaml
alias: Звонок в домофон — уведомление со снимком
triggers:
  - trigger: state
    entity_id: event.fanvil_i60k_doorbell
actions:
  - action: camera.snapshot
    target:
      entity_id: camera.fanvil_i60k_main_stream
    data:
      filename: /config/www/doorbell.jpg
  - action: notify.mobile_app_phone
    data:
      message: "Звонят в дверь"
      data:
        image: /local/doorbell.jpg
```

## Как работают события

Если Action URL включён, интеграция прописывает в настройки панели `cti.*` адреса вида
`http://<home-assistant>:8123/api/webhook/<id>?event=incoming&remote=$remote…` — по одному на событие.
Панель отправляет HTTP GET при каждом событии.

- Пишутся только **пустые** ключи или ключи, уже указывающие на эту интеграцию. Адрес другой системы
  остаётся как есть — такое событие работает только через опрос, а датчик *Action URL* показывает
  `partial` и список таких событий.
- Выключение Action URL или удаление интеграции стирает **только свои** адреса.
- Раз в 10 минут адреса сверяются заново (автонастройка или сброс панели могут их стереть).
- Вебхук принимает запросы только из локальной сети и только с MAC-адреса панели.

### Дверной звонок

Нажатие кнопки вызова приходит в Home Assistant событием Action URL `key`, а если кнопка набирает
номер, — ещё и исходящим звонком `outgoing`. Сущность *Звонок в дверь* превращает оба в один `ring`
(повторы в течение 15 с отбрасываются). Кнопка по-прежнему звонит в квартиру, а Home Assistant
одновременно получает дверной звонок.

### Журнал открытий

Панель сама ведёт журнал открытий и неудачных попыток. Интеграция читает его сразу после
срабатывания реле и раз в минуту (чтобы ловить отказы) и ничего в нём не меняет. PIN-коды никуда не
передаются. Отправка журнала на сервер (`doorphone.RelayLog*`) не трогается: её часто использует
облачное управление Fanvil.

### Динамик

Панель сама скачивает звук из Home Assistant. Прошивка 2.12.51 понимает только WAV, поэтому любой
звук (синтез речи, медиа, ссылка) перекодируется через ffmpeg в WAV 16 кГц моно и отдаётся по
случайному одноразовому адресу 5 минут. Панель должна доставать до адреса Home Assistant из
датчика *Action URL* (или заданного в параметрах).

### Звук в камере

*Звук в камере* включает микрофон в обоих потоках RTSP. Панель отдаёт G.711 (8 кГц): живой
просмотр играет его через WebRTC (go2rtc, входит в стандартную конфигурацию). Запасной HLS в
Home Assistant умеет только AAC и MP3 — там видео будет без звука.

## Особенности прошивки

Учтены в интеграции, перечислены для диагностики (i60K, прошивка 2.12.51):

- API отдаёт JSON с `Content-Type: text/html`; без авторизации — страницу входа с HTTP 200.
- Сразу после ответа панель ~0,3 с отвергает следующий запрос — между запросами пауза 0,5 с.
- После команды реле чтение может вернуть HTML-заглушку — чтение повторяется, команды не повторяются никогда.
- При загрузке панель недолго показывает страницу входа — повторный вход запрашивается, только если это не проходит.
- Ключи `cti.CallRemoteCanceledUrl` и `cti.RejectIncomingCallUrl` эта прошивка не принимает.

## Если что-то не работает

- **Не добавляется:** проверьте, что HTTP API включён и логин/пароль именно от API
  (*Intercom Settings → Features → Basic Settings*). После нескольких неверных паролей API временно
  блокируется. Точная причина — в журнале Home Assistant.
- **Нет мгновенных событий:** посмотрите датчик *Action URL* и его атрибуты; панель должна
  доставать до указанного там адреса Home Assistant — иначе задайте его в параметрах.
- **Диагностика:** страница устройства → ⋮ → *Скачать диагностику* (пароли, MAC и серийный номер скрыты).

## Планы

- **Кнопка вызова только для Home Assistant:** параметр, переключающий функциональную клавишу
  панели так, чтобы нажатие только отправляло HTTP-запрос в Home Assistant (без SIP-звонка), —
  чистый умный дверной звонок.
- **Гостевые коды:** временные PIN-коды и карты с расписанием (`api/persons`, `api/period`).
- **Управление звонком:** набрать номер и сбросить вызов из Home Assistant.
- **Самотест:** кнопка встроенной проверки динамика и микрофона.
- **Решение о доступе на стороне сервера** (прошивка 2.12.55+): Home Assistant решает, открывать ли
  дверь по карте или PIN-коду.
- Больше устройств: i61–i68, внутренние мониторы, интеркомы.

## Разработка

```bash
python3 -m venv .venv
.venv/bin/pip install aiohttp pytest pytest-asyncio ruff
.venv/bin/pytest -q
.venv/bin/ruff check . && .venv/bin/ruff format --check .
```

API-клиент (`custom_components/fanvil/api.py`) не зависит от Home Assistant и тестируется на
локальном HTTP-сервере. `scripts/probe.py` — проверка реальной панели только чтением.

Источники: Fanvil HTTP API Manual V0.8.7.3, Fanvil Action URL and Active URI Specification V0.0.5.
